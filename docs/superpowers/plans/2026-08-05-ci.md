# CI на GitHub Actions — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** каждый push в `main` и каждый PR автоматически прогоняют 187 тестов на настоящем PostgreSQL, линт и сборку фронтенда.

**Architecture:** один файл `.github/workflows/ci.yml`, два независимых job'а. `backend` поднимает сервис-контейнер `postgres:17-alpine`, ставит зависимости через `uv` и гонит ruff + pytest + две дополнительные проверки (страж пропусков, дрейф миграций). `frontend` собирает Mini App (`tsc -b && vite build`). Job'ы не зависят друг от друга и падают по отдельности.

**Tech Stack:** GitHub Actions, `astral-sh/setup-uv`, `actions/setup-node@v4`, Python 3.12, Node 22, PostgreSQL 17, pytest, ruff, alembic.

**Спек:** `docs/superpowers/specs/2026-08-05-ci-design.md`

## Global Constraints

- Python в CI — **3.12**, без matrix: это версия продакшн-образа (`python:3.12-slim`). Локальные 3.14 воспроизводить не надо.
- Node — **22** (`node:22-alpine` в `Dockerfile`).
- Установка зависимостей — **`uv sync --frozen --extra dev`**. Без `--extra dev` не будет `pytest` и `aiosqlite`: они объявлены в `[project.optional-dependencies].dev`, а в `[dependency-groups]` лежит только `ruff`.
- Триггеры — `push` в `main` и любой `pull_request`. Path-фильтры не использовать.
- Линтуются каталоги `core/ bot/ api/ tests/` — ровно как в `CLAUDE.md` → `## Commands`.
- `ruff format --check` на текущем `main` проходит (`69 files already formatted`), ослаблять до `ruff format` не требуется.
- Секреты не нужны: `tests/env.py` пинит окружение сам, `.env` в CI отсутствует и это часть проверки.
- Репозиторий публичный, минуты Actions бесплатны — оптимизировать время прогона не требуется.

### Task 1: Workflow с обоими job'ами

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `pyproject.toml` (`--extra dev`), `webapp/package-lock.json`, `tests/test_concurrency.py` (читает `TEST_DATABASE_URL`), `alembic/env.py` (читает настройки через `core.config.get_settings`, которому обязательны `BOT_TOKEN`, `ZAI_API_KEY`, `DATABASE_URL`).
- Produces: job'ы с именами `backend` и `frontend` — на них будет ссылаться Task 2 и, при желании владельца, branch protection.

- [ ] **Шаг 2: Написать `.github/workflows/ci.yml` целиком**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

# Новый push отменяет незавершённый прогон того же ref.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  backend:
    runs-on: ubuntu-latest

    services:
      postgres:
        image: postgres:17-alpine
        env:
          POSTGRES_USER: user
          POSTGRES_PASSWORD: password
          POSTGRES_DB: racetest
        ports:
          - 5432:5432
        options: >-
          --health-cmd "pg_isready -U user -d racetest"
          --health-interval 5s
          --health-timeout 3s
          --health-retries 10

    env:
      # Без этой переменной tests/test_concurrency.py молча пропускается — см. шаг «страж».
      TEST_DATABASE_URL: postgresql+asyncpg://user:password@127.0.0.1:5432/racetest

    steps:
      - uses: actions/checkout@v4

      - uses: astral-sh/setup-uv@v5
        with:
          enable-cache: true
          python-version: "3.12"

      # --extra dev обязателен: pytest и aiosqlite лежат в optional-dependencies,
      # а не в dependency-groups (там только ruff).
      - name: Установить зависимости
        run: uv sync --frozen --extra dev

      - name: ruff check
        run: uv run ruff check core/ bot/ api/ tests/

      - name: ruff format --check
        run: uv run ruff format --check core/ bot/ api/ tests/

      - name: Тесты
        run: uv run pytest -q

      # Тесты конкурентности стерегут _lock_item() и SELECT … FOR UPDATE, то есть деньги,
      # и пропускаются молча без TEST_DATABASE_URL. Опечатки в переменной хватило бы,
      # чтобы CI годами показывал зелёное на 182 тестах вместо 187.
      - name: Конкурентность действительно исполнилась
        run: |
          set -o pipefail
          uv run pytest tests/test_concurrency.py -q | tee /tmp/concurrency.txt
          if grep -q skipped /tmp/concurrency.txt; then
            echo "::error::тесты конкурентности пропущены — TEST_DATABASE_URL не доехал до раннера"
            exit 1
          fi

      # Миграции PostgreSQL-only (f1a2b3c4d5e6 использует ctid и DELETE … USING), SQLite
      # их не видит никогда — до этого шага их не проверяло ничто, кроме деплоя.
      - name: Модели и миграции не разъехались
        env:
          BOT_TOKEN: "1234567890:ABCdefGHIjklMNOpqrsTUVwxyz"
          ZAI_API_KEY: ci
          DATABASE_URL: postgresql+asyncpg://user:password@127.0.0.1:5432/migcheck
        run: |
          set -euo pipefail
          # Отдельная база: racetest уже засеян таблицами из тестов конкурентности.
          PGPASSWORD=password psql -h 127.0.0.1 -U user -d racetest -c 'CREATE DATABASE migcheck'
          uv run alembic upgrade head
          uv run alembic revision --autogenerate -m ci-drift-check
          python - <<'PY'
          import pathlib, re, sys

          newest = max(pathlib.Path("alembic/versions").glob("*.py"), key=lambda p: p.stat().st_mtime)
          body = re.search(r"def upgrade\(\).*?:\n(.*?)\ndef downgrade", newest.read_text(), re.S)
          lines = [
              line.strip()
              for line in (body.group(1) if body else "").splitlines()
              if line.strip() and not line.strip().startswith("#")
          ]
          if lines != ["pass"]:
              print("::error::autogenerate дал непустую миграцию — модели и схема разъехались")
              print("\n".join(lines))
              sys.exit(1)
          newest.unlink()
          PY

  frontend:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: webapp

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
          cache-dependency-path: webapp/package-lock.json

      - name: Установить зависимости
        run: npm ci

      # tsc -b && vite build. Ошибка типов сегодня всплывает только на сборке образа,
      # то есть через 19 минут и уже во время деплоя.
      - name: Сборка Mini App
        run: npm run build
```

### Task 2: Доказать, что CI краснеет

**Files:**
- Modify: `README.md` (бейдж в шапке), `CLAUDE.md` (раздел `## Commands`)

**Interfaces:**
- Consumes: job'ы `backend` и `frontend` из Task 1.
- Produces: ничего для последующих задач; это проверочная задача.

Зелёный прогон не доказывает ничего: workflow, который не запускается, тоже не краснеет. Ниже три намеренных поломки. Каждая делается **временным** коммитом в ту же ветку и откатывается сразу после проверки.

**Ловушка `gh run watch`:** без аргумента команда цепляется к самому свежему прогону, а он в момент запуска может быть ещё предыдущим — тогда она покажет зелёное от старого коммита. Перед каждым `watch` убедитесь, что прогон именно для вашего SHA:

```bash
sleep 10
gh run list -L 3 --json headSha,status,conclusion,databaseId
gh run watch <databaseId> --exit-status
```

## Приёмка задачи целиком

1. `gh run watch --exit-status` на финальном коммите ветки — зелёный.
2. В логе `backend` — `187 passed`, не `182 passed, 5 skipped`.
3. Проверено, что CI краснеет: на падающем тесте, на отломанном `TEST_DATABASE_URL`, на ошибке типов во фронтенде.
4. `git log` не содержит `tmp:`-коммитов без отката.
5. Бейдж в `README.md` показывает `passing`.

## Вне объёма

- Сборка Docker-образа в CI, деплой, публикация артефактов, coverage-пороги.
- Branch protection и required checks: это настройка на GitHub, а не файл в репозитории — включает владелец вручную.
- Pre-commit — следующая задача.
- Matrix по версиям Python.
